1. Positioning

One-liner: "An autonomous AP agent with hard separation of duties. Claude reads the documents and explains; deterministic policy decides; the database enforces who can approve. Proven on freight, where payment-redirect fraud is worst."

The pitch is not "AI pays invoices". The pitch is that the model is structurally unable to pay anyone: it produces typed fields and prose, the policy ignores the prose, the reducer recomputes from trusted rows, and the agent identity cannot approve. Freight is the proving ground because payment-redirect fraud against brokers is common, expensive, and has a clean verifiable artifact (the notice of assignment).

2. Architecture (solo slice)

01 · READDocuments → typed facts

Rendered PDFs go to Claude vision. It returns typed invoice fields, a confidence, and an explanation. A labeled manual-extraction fallback exists until sponsor credits arrive.

02 · DECIDErules.ts, two call sites

The agent runs evaluateSettlement to explain. The Spacetime reducer imports the same file unchanged and re-evaluates inside the transaction that reserves the obligation.

03 · ENFORCESpacetimeDB

Identity boundary and transaction boundary are the same boundary. Unique indexes are the reservation. The landing hero, the AP tab and the controller tab are all live subscriptions.

  5. 1:35–2:00 Evidence. Scorer numbers, REAL / SIMULATED / NOT BUILT.

Do not demonstrate a controller being refused merely because the agent requested payment. The requester and approver must be different identities with appropriate permissions; that is the point.

9. Prepared judge answers

  • Why Spacetime over Postgres? Identity boundary and transaction boundary are the same boundary; no API server to get wrong; live sync is free.
  • Prompt injection via a document? LLM outputs typed fields and prose only. Policy ignores prose; reducers recompute from trusted rows; the agent identity cannot approve.
  • How does it learn policy? It doesn't yet. Explicit, auditable policy is the point for AP. Learning is the next milestone.
  • TriumphPay? Payment rail, not the evidence-backed payee decision.
